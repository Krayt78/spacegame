# Nexus Protocol → `@parity/product-sdk` migration plan

> **Status: Phases 1–4 complete (dev-mode verified). Phase 5 (real host) and Phase G (PAPI reads) pending.**
>
> **Supersedes** [`HOST_SIGNING_PLAN.md`](./HOST_SIGNING_PLAN.md). Phase 1 lessons in [`HOST_SIGNING_PHASE_1_LESSONS.md`](./HOST_SIGNING_PHASE_1_LESSONS.md) still apply (hydration `mounted` gate, no `return null` during transitions, dot.li service-worker cache audit after every deploy, env vars baked at build time for static export).

## TL;DR

Nexus Protocol's frontend has been migrated off MetaMask + ConnectKit + a hand-rolled `pallet_revive::call` pipeline onto **`@parity/product-sdk-*`** (Parity-published, sits on top of the v0.7 triangle stack). Authentication is now a Polkadot Host login (or the local `DevProvider` for fast iteration); writes go through `ContractManager.<method>.tx()` with automatic dry-run + account-mapping; reads stay on wagmi + eth-rpc for now.

**End-state numbers**:
- `node_modules`: dropped to 808 packages (down from ~1057 mid-migration, smaller than the pre-migration baseline).
- `frontend/src/hooks/useNexusGame.ts`: 1502 lines (down from 1923).
- Removed: `connectkit`, `@novasamatech/host-papp`, `@novasamatech/statement-store`, `@polkadot-api/substrate-bindings`, and ~7 hand-rolled glue files.
- Added: `frontend/src/lib/triangle/` (3 small singletons), `frontend/src/hooks/useTriangle.ts`, `frontend/src/hooks/useNexusContractWrite.ts`, `frontend/cdm.json` + `frontend/.cdm/contracts.d.ts` (both generated).

## What `@parity/product-sdk` is, in one paragraph

`paritytech/product-sdk` is an Apache-2.0 monorepo published under `@parity/product-sdk-*` (we run 0.5.x / 0.4.x / 0.3.x / 0.2.x — see versions in `package.json`). It wraps the v0.7 triangle stack and adds typed, ergonomic APIs for pallet-revive contract calls with dry-run preflight + automatic account mapping, multi-provider signer management with subscribe-pattern state, host-routed PAPI client, and a `cdm.json` manifest that pins each contract to an address + ABI per target chain, with codegen producing full TypeScript types for every method call.

| Package | Replaces in our codebase |
| --- | --- |
| `@parity/product-sdk-contracts` | `useReviveCall.ts`, `useReviveContractWrite.ts`, manual ABI plumbing |
| `@parity/product-sdk-signer` | `useSpektrAccounts.ts`, the singleton+polling fallback machinery |
| `@parity/product-sdk-host` | `lib/host/hostEnv.ts` (`isInsideContainerSync`), `lib/host/pappAdapter.ts` |
| `@parity/product-sdk-address` | `lib/host/addressMapping.ts` (`accountIdToH160` → `deriveH160`) |
| `@parity/product-sdk-tx` | The dry-run + `signSubmitAndWatch` flow inside `useReviveCall.ts` |

## Decisions (confirmed during execution)

1. **Account model**: **legacy accounts**, not product accounts. The original plan said `('nexus-protocol.dot', 0)`. During execution we learned that the `SignerManager.connect("host")` happy path exposes legacy accounts (the user's regular host-paired wallet) and that's what the existing read hooks have been querying against. Switching to product accounts would have produced a different H160 → orphaned existing testnet state. Pre-launch this is fine to change later via `derivationIndex` if needed.
2. **Login reason string** (shown in host UI): `"Sign in to play Nexus Protocol"`. **UPDATE during Phase 5**: `requestLogin` is a v0.7 protocol method and our installed `@novasamatech/product-sdk` is v0.6 — we can't trigger the host's native login UI from the product. The dApp now relies on the user already being signed into dot.li before opening the dApp; the "Sign in" button just retries `signerManager.connect('host')`. Reintroduce `requestLogin` when we bump to v0.7.
3. **ConnectKit teardown**: completed in Phase 4, immediately after Phase 3 went green in dev mode.
4. **PAPI-only reads (Phase G)**: deferred. Reads stay on wagmi + eth-rpc.

## Phase status

### Phase 1 — SDK install + cdm.json + codegen ✅

**Added**:
- `frontend/cdm.json` — generated by `scripts/generate-cdm.mjs` from `NEXT_PUBLIC_NEXUS_GAME_ADDRESS` + `NEXT_PUBLIC_GAME_CONFIG_ADDRESS` + on-disk ABIs. Two libraries: `@nexus/game` and `@nexus/config`.
- `frontend/scripts/generate-cdm.mjs`, `frontend/scripts/generate-contract-types.mjs`.
- `.cdm/contracts.d.ts` (gitignored) — augments the `Contracts` interface so `manager.getContract("@nexus/game").upgradeBuilding.tx` is fully typed from the Solidity ABI.
- `tsconfig.json` includes `.cdm/**/*.d.ts`. `.gitignore` excludes `frontend/cdm.json` and `frontend/.cdm/`.
- npm scripts: `gen:cdm`, `gen:types`, `gen`, `prebuild:static`. `dev:local`/`dev:testnet` wrap codegen + `next dev` inside `env-cmd` via `sh -c`.

**Deviation**: the `@parity/product-sdk-descriptors/paseo-asset-hub` descriptor the plan recommended targets `wss://paseo-asset-hub-next-rpc.polkadot.io` (genesis `0x173cea…`). Our contracts are deployed against `wss://asset-hub-paseo.dotters.network` (genesis `0xd6eec…`). Two different chains. We kept our existing `.papi/descriptors` (regenerated against polkadot-api v2 in Phase 3) and pin `NEXT_PUBLIC_HUB_WS_URL=wss://asset-hub-paseo.dotters.network` in every env file.

### Phase 2 — Wire SignerManager + sign-in UI ✅

**Added**:
- `frontend/src/lib/triangle/signerManager.ts` — singleton `SignerManager({ ss58Prefix: 0, dappName: "nexus-protocol" })`.
- `frontend/src/hooks/useTriangle.ts` — subscribes to `signerManager`, auto-`connect('host')` on mount (silent failure → user clicks button), exposes `signIn()` that runs `accountsProvider.requestLogin('Sign in to play Nexus Protocol')` + retry connect. Preserves the `mounted` SSR gate.

**Rewritten**:
- `frontend/src/hooks/useHostAddress.ts` → thin shim over `useTriangle()`. Existing call shape preserved; the ~8 consumers across `useNexusGame`, `ProtectedRoute`, `GameHeader`, `GameLayout`, `BattleReportCard`, `settings`, `galaxy` all keep working unchanged.
- `frontend/src/app/page.tsx` — explicit "Sign in to play Nexus Protocol" button.

**Added bonus**: `NEXT_PUBLIC_SIGNER_PROVIDER=dev` env switch — flips `signerManager.connect('dev')` (DevProvider, Alice/Bob from the well-known Substrate mnemonic). Saves a dot.li upload per iteration. See `.env.localhost` (defaulted to `dev`) vs `.env.testnet` (no value → `host`).

**Deviation from plan**: `chainClient.ts` and `contractManager.ts` were NOT created in Phase 2 — they'd have been unused until Phase 3 anyway, and they pull in the descriptor + polkadot-api-v2 question we deferred to Phase 3.

### Phase 3 — Rewire writes onto `ContractManager` ✅

**Bumped**: `polkadot-api` from `^1.23.3` to `^2.0.0` at root. Existing `.papi/descriptors` regenerated via `npx papi` to match.

**Added**:
- `frontend/src/lib/triangle/chainClient.ts` — singleton `PolkadotClient`. Inside a host, tries `getHostProvider(genesis)` first (host-routed RPC). Outside, falls back to `getWsProvider(NEXT_PUBLIC_HUB_WS_URL)`. Critical: not using `createChainClient` from `@parity/product-sdk-chain-client` because that package is **host-only** — no direct WS fallback — which would have broken dev mode.
- `frontend/src/lib/triangle/contractManager.ts` — singleton `ContractManager` bound via `ContractManager.fromClient(cdmJson, client, paseoHubDescriptor, { signerManager })`. Uses our local `hub` descriptor (from `.papi/descriptors`) instead of the SDK's `paseo_asset_hub` (different chain). Also exposes `ensureMapped(ss58, signer)` for the one-time `Revive.map_account`.
- `frontend/src/hooks/useNexusContractWrite.ts` — shared write hook. Process-wide memoization of mapped accounts. Accepts both new clean signature `useNexusContractWrite([invalidate])` and legacy `useNexusContractWrite({ contractAddress, abi, invalidate }, tag)` shape (so the 19 write hooks needed only a rename, not a body rewrite). `call('@nexus/game', 'method', args)` is the new form; `call('method', args)` defaults to `@nexus/game`.

**Rewritten**:
- `frontend/src/hooks/useNexusGame.ts` — all 19 write hooks now flow through `useNexusContractWrite`. Read hooks (~30+) untouched. `nexusGameAbiTyped: unknown = nexusGameAbi` is a placeholder kept around for the legacy options shape; will be cleaned up in the optional Phase 3 polish.

**Deleted**: `useReviveCall.ts`, `useReviveContractWrite.ts`, `useSpektrAccounts.ts`, `lib/papiClient.ts`, `lib/host/hostEnv.ts`, `lib/host/addressMapping.ts`, `lib/host/pappAdapter.ts`. The `lib/host/` directory is gone entirely.

**Issues hit and fixed during execution**:
- `@polkadot-api/json-rpc-provider-proxy` (transitive) imports `@polkadot-api/json-rpc-provider`, which wasn't getting hoisted under Turbopack. Fix: added `@polkadot-api/json-rpc-provider: ^0.2.0` as a direct dep.
- `polkadot-api/ws-provider/web` (v1 path) no longer exists in v2 — moved to `polkadot-api/ws`. One-line import fix in `chainClient.ts`.
- The dry-run for `claimStarterPlanet` failed with `StorageDepositNotEnoughFunds` when Alice's SS58 had no PAS. **This was the correct on-chain behavior, not a code bug** — fund Alice's SS58 on Paseo Asset Hub via https://faucet.polkadot.io/.

### Phase 4 — Tear out connectkit + WalletConnect ✅

**Deleted dep**: `connectkit`, `@novasamatech/host-papp`, `@novasamatech/statement-store`, `@polkadot-api/substrate-bindings`. Kept: `@novasamatech/product-sdk` (dynamically imported at runtime by `@parity/product-sdk-signer`'s `HostProvider` for real-host mode).

**Deleted code**: `frontend/src/components/ui/NetworkGuard.tsx` (passthrough since Phase 1 of the old plan; import removed from `app/game/layout.tsx` + export removed from `components/ui/index.ts`). `frontend/public/papp-metadata.json` (was needed for `host-papp`'s PWallet QR confirmation — `dot.li` doesn't use it).

**Env churn**: removed `NEXT_PUBLIC_WALLETCONNECT_PROJECT_ID` from `.env.localhost`, `.env.testnet`, `.env.production`, `.env.example`. Added `NEXT_PUBLIC_HUB_WS_URL` documentation to `.env.example` and value to `.env.production`.

**Verified**: all four top-level routes (`/`, `/game`, `/game/onboarding`, `/game/settings`) still return 200 from `npm run dev:local`.

### Phase 5 — Real-host sanity check (NOT YET DONE — the ship gate)

Everything above was verified in **dev mode** (`NEXT_PUBLIC_SIGNER_PROVIDER=dev`, Alice via DevProvider). The real-host code path through `accountsProvider.requestLogin('Sign in to play Nexus Protocol')` + `HostProvider.connect()` has **never been exercised end-to-end on this build**.

Deploy to dot.li (`scripts/deploy-frontend.sh`), open at `https://my-nexus42.dot.li` (or whatever domain), and verify:

1. Standalone browser → "Open in Polkadot Host" message.
2. Inside dot.li, signed out → "Sign in to play Nexus Protocol" button → host's native login UI fires → redirect to `/game`.
3. Inside dot.li, already signed in → auto-connect, no button flash.
4. `Claim Planet` → phone prompts twice (first time, for `Revive.map_account`), then once per write thereafter.
5. The H160 in the UI matches what your existing testnet planet (if any) is stored under.

If `requestLogin` returns `LoginErr.Unknown("Not implemented")` on the live dot.li build, fall back to the silent auto-connect path (the existing flow Phase 1 used) until the host catches up — `useTriangle.signIn` already tolerates a failed `requestLogin` and proceeds to `connect` anyway.

### Phase G — PAPI-only reads (DEFERRED)

Out of scope for this migration. Reads still go through wagmi/eth-rpc. To revisit if eth-rpc proxy reliability becomes a problem: replace `useReadContract` with `manager.getContract(library).<method>.query()` from `@parity/product-sdk-contracts`. ~30 mechanical hook refactors.

## Optional follow-ups

1. **Phase 3 cosmetic cleanup** (~15 min, pure tidying):
   - Drop the `LegacyOptions` overload + `_legacyLogTag` param from `useNexusContractWrite`.
   - Drop the `nexusGameAbiTyped: unknown = nexusGameAbi` placeholder from `useNexusGame.ts`.
   - Rewrite the 19 hook bodies to `useNexusContractWrite([...invalidate])` (no second arg, no abi/contractAddress in the options).
   - Drops ~50 lines of dead code, no behavior change.

2. **Phase G — PAPI-only reads**: see above. Only do this if eth-rpc reliability becomes a problem.

3. **Bump `@parity/product-sdk-*` versions over time.** They're 0.x — expect minor-version churn. Pin exactly and bump deliberately.

4. **Investigate `@parity/host-api-test-sdk/playwright`** for automated e2e tests of the sign-in flow. Used by the SDK's own demos; would catch regressions without needing a dot.li deploy.
